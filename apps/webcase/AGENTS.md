# apps/webcase

Webcase is a personal replacement for Pocket: a library of saved links. You save a link, it picks up the title, description and image, you tag it, and Home is one list with search and tag filters. It is an installable web app (PWA, no notifications) used mostly on a phone. Sign-up is open and each user sees only their own links. TanStack Start + React 19 (Router, Query, Form), Vite 8, Tailwind 4, shadcn on Base UI (tabler icons), Convex, Better Auth (email and password) through `@convex-dev/better-auth`.

Commands, run in `apps/webcase`: `bun run dev` (port 3000), `bun run build` (nitro, Vercel output), `bun run typecheck`, `bun run lint` (oxlint), `bun run check` / `bun run format` (prettier). There are no tests. `bunx convex dev --once` pushes functions to the dev deployment and regenerates `convex/_generated`. Commit the regenerated files.

- `src/routes/` holds TanStack file routes and stays thin. `src/screens/<area>/index.tsx` are the page bodies, with their own pieces as siblings (`screens/home/AskResults.tsx`); split a screen or component once it holds several stateful parts. Unknown URLs and errors while loading or rendering a page show `screens/not-found` and `screens/error`, the router's defaults in `src/router.tsx`; the error screen shows the error text only in development. `src/modules/<area>/` hold the data layer and domain logic; e.g. `src/modules/link/utils.ts` has `groupByMonth` and `countTags`. The file kinds in a module:
  - `queries.ts` / `mutations.ts`: hooks over the Convex functions. Each `api.modules.<area>.*` function is wrapped once, in its own module (`modules/link` wraps every link query, mutation and action, including `useLibrary` with links, tag counts and status); other modules (`save`, `import`) build their orchestration on those wrappers. Stateful mutations use TanStack's `useMutation` unless one run spans many calls (the import runner, which says why).
  - `schema.ts`: zod schemas and the types derived from them, e.g. a route's search params (`modules/save/schema.ts`). Text search params use `searchText` from `src/lib/searchParams.ts`, because the router JSON-parses values (`?title=2048` is a number).
  - `errors.ts` (`modules/link`): `ErrorMessages<typeof fn>` keys copy by a function's error union, so a new server code is a type error; `messageFor` adds the generic fallback; `MESSAGES` is the one wording for codes that recur (`UNAUTHORIZED`, `INVALID_URL`, `NOT_FOUND`, `LIBRARY_FULL`, `NETWORK` for any call that threw); `UPDATE_TAGS_MESSAGES` maps `updateTags` once for the sheet and Save.
  - `hooks.ts`: React hooks with domain knowledge, e.g. `useReturnToLibrary` (go back to Home when Home opened the page or the save sheet, else replace) and `useSaveDraft`. A screen's own hooks sit beside it (`screens/home/hooks.ts`, the `/` search shortcut).
  - `utils.ts`: pure domain helpers. Narrower pure files are named for what they hold: `search.ts` (browser search), `share.ts` (system share sheet / copy), `csv.ts` and `pocket.ts` (the export parser), `file.ts` (reading a chosen file).
  - `components/`: components that use the module's data.
  - `modules/auth` also has `client.ts` (the Better Auth browser client), `service.ts` (sign in, up and out through it, with the error copy), `server.ts` (server only: the `/api/auth` proxy handler and the SSR token), `functions.ts` (the server function that reads the token) and `guards.ts` (route `beforeLoad` guards).
- `/` and `/save` share the pathless layout `src/routes/_library.tsx`, which validates `tag`, runs the sign-in guard and draws Home with the save sheet (`screens/save`) over it, so opening and closing the sheet never remounts the library or loses its scroll, search or filter. `/save` stays a real URL with its own search params (`url`, `title`, `text`, `modules/save/schema.ts`): the share target in `public/manifest.json`, direct links and the sign-in redirect open it cold, as the library with the sheet open. The sheet opens and closes from the location (`useLocation`), which changes as soon as a navigation starts, not from the matched route, which waits for the root's auth round trip; `routes/_library/save.tsx` holds only the schema and title. Closing goes back when the library opened it (`FROM_LIBRARY` history state), else replaces with `/`; links into it and its own URL updates pass `resetScroll: false` so the library behind keeps its place. A save on its way cancels any close but Back. `/import` is still a full page.
- Link scheme. The manifest's `protocol_handlers` registers `web+webcase` for the installed desktop app (Chrome and Edge on Windows, macOS and Linux; not Android or iOS), so another app (an iOS/macOS Shortcut, a script, Raycast) opens the installed app rather than a browser tab: `open "web+webcase:https://example.com"`. Two forms: `web+webcase:<link>` (the link as is or URL-encoded once; its own query and fragment survive) and `web+webcase://save?url=…&title=…&text=…` (/save's params, encoded). The OS opens `/open?link=<the whole web+webcase: URL, encoded>` (`routes/open.tsx`, signed-in only), which replaces itself with `/save?…` or, when there is no link, `/`. The payload is untrusted (any page can open such a link): `parseSchemeLink` (`modules/save/scheme.ts`, pure) only ever yields a /save payload whose `url` passed the shared-link checks (`toHttpUrl` for the first form, `findSharedUrl` for the second), never a place to go, and nothing is saved until Save is tapped. Chrome asks once, on the first launch through the scheme, whether the app may open these links.
- Sheets and the on-screen keyboard. On a touch screen (`isTouchScreen`, `src/lib/touch.ts`) nothing focuses a text field by itself: a sheet opens with focus on its title (the save sheet) or a control (the detail sheet's Open), and entering a link, Change, a failed Paste link or Continue leave the keyboard down; it rises only when a field is tapped. With a mouse and keyboard, the save sheet focuses the link field, then the tag field. Base UI's `Drawer.VirtualKeyboardProvider` (`components/ui/drawer.tsx`) is the only thing that handles the keyboard: it pins the page, sets `--drawer-keyboard-inset` and scrolls the focused field into view, and the popup pads its bottom by that inset, so the body and a pinned footer (Save) end above the keyboard. Never add a second keyboard measurement (a spacer from `visualViewport`): it lands a render after Base UI has measured without it, and both lifts apply.
- `src/hooks/` holds generic hooks with no domain knowledge, one per file: `useClientDates` (the device's `now` and zone, null during SSR and hydration), `useRenderLimit` (render a long list a page at a time). `src/lib/` holds app plumbing (the Convex client, search-param parsing, `isTouchScreen`). `src/components/` holds only presentational pieces and the shadcn kit (`ui/`), e.g. `PageHeader` (the `‹ Library` header of a sub-page) and `SectionLabel` (the letter-spaced caps label); `src/components/lib/` keeps only pure display helpers (`cn`, the tag colour hash, date formatting). Providers are composed inline in `src/routes/__root.tsx`. Aliases: `@/` → `src/`, `@convex/` → `convex/`, `@shared/` → `shared/`.
- `shared/` holds rules both sides must agree on, as plain TypeScript that imports nothing outside `shared/`: `tags.ts` (`normalizeTag`, `normalizeTags`, `MAX_TAG_LENGTH` 40, `MAX_TAGS` 20, the `TagCount` type), `limits.ts` (URL, title, description, domain, image, question and import-batch limits, the import pace `IMPORT_SPACING_MS`, `DAILY_IMPORT_LIMIT` 1,000, `MAX_LINKS_PER_USER` 5,000, `SUMMARY_STUCK_AFTER_MS`, `MIN_PASSWORD_LENGTH`), `auth.ts` (the headers the auth proxy uses to pass on the browser's IP) `url.ts` (`parseHttpUrl`, the normaliser links are stored and matched by, which drops the `TRACKING_PARAMS` and unwraps redirect wrappers; `domainOf`; `fallbackTitle`, the title of a link when neither its site rule nor its page gave one, which the save sheet also shows while the preview loads: the title its site rule takes from the URL, else host and path (`hostPathTitle`); `isPlaceholderTitle`, which counts those, the URL itself in any spelling (a wrapper's and its destination's), the bare domain and the titles a site rule lists as naming nothing as stand-ins, and nothing else: a real title that reads like its slug stays) and `sites/` (the URL-only parts of the site rules, below). `src` imports it as `@shared/…`; Convex imports it by relative path (`../../../shared/tags`), which its bundler resolves without the alias. Never redeclare these rules elsewhere, and never import Convex code into `src` for them.
- Convex: `convex/modules/<area>/{schema,queries,mutations,helpers}.ts`. Every action goes in `nodeActions.ts`, which starts with `'use node'` and runs in the Node runtime (public ones are called as `api.modules.<area>.nodeActions.<name>`); `ai.ts` beside it holds the model calls and prompts those actions use, and is Node-only too. `convex/lib/` holds server helpers the modules use: `lib/metadata/url.ts` (which URLs and addresses may be fetched: the IANA special-purpose ranges are refused) and `parse.ts` (HTML parsing) and `lib/text.ts` are pure; `lib/metadata/fetch.ts` is `'use node'` network I/O (the DNS-pinned fetch: `fetchPage` for pages, which also reports every URL its redirects went through, `fetchJson` for site endpoints and `locateRedirect` for where a share link goes, one guarded path), and so is `lib/metadata/read.ts` (`readLink`, see Site rules below), so only Node actions import them, and `convex/configs/` the shared setup (the AI provider, the rate limiter with its per-user and global buckets). Handlers return `{ error: 'CODE' }` instead of throwing, and mutations that have nothing else to return give `{ success: true }`.
- Site rules. The owner's rule: when a URL is looked at, it is matched against the special rules we have; if one matches, that rule handles it; if not, it goes to the base workflow (the page's own metadata). Special handling is always the exception, never the base rule, and rules are added over time. `readLink` (`convex/lib/metadata/read.ts`, called by `preview` and `enrich`) and the normaliser (`parseHttpUrl`) consult the rules first; a link none matches gets the generic page fetch (`fetchPage`) and nothing else.
  - A rule has a name, a pure `match(url)` and only the hooks it needs: (1) **rewrite**, the link is really another URL, resolved before anything is read: a redirect wrapper's destination written in its query (pure, applied by the normaliser, so the destination is what is stored, matched and read), or where a share link redirects to (`locate`, read-time only, the stored URL stays); (2) **resolve**, the site's own endpoint (oEmbed, an API), fetched alongside the page; (3) **cleanPage**, fixing what the page read: `cleanPage` (null when the page is not the content, which then counts as unread), `cleanTitle` (the site's decoration removed; also applied to stored titles, so a decorated title is replaceable) and `isGenericDescription`; (4) **from the URL**, a title or description taken from the URL or the redirects it went through, used only for fields nothing else filled: `title` in `shared/sites` (the save sheet's fallback too) and `fromUrl(redirects, read)` on the server. `provides` says which fields resolve or fromUrl fill for that link, for re-enrichment.
  - Where the files are: each rule is one file per side under one name. The URL-only part (match, wrapper rewrite, URL title, `placeholderTitles`) is `shared/sites/<site>.ts`, listed in `shared/sites/index.ts`, because the browser needs it and it imports nothing outside `shared/`. The network part (share rewrite, resolve, cleanPage, fromUrl) is `convex/lib/metadata/sites/<site>.ts` (`Site`, `sites/types.ts`), listed in `sites/index.ts`; it imports the shared part's `match` and constants rather than listing the site's hosts again. A rule has one side or both.
  - To add a rule: write its file(s) and list them in the index; never add a second HTTP path (every request goes through `fetchPage`, `fetchJson` or `locateRedirect`, which re-validate and pin each hop). Every new rule needs (a) a verified real example: the URL shapes, redirects and page shapes it relies on checked with live requests, and anything that could not be checked left out; and (b) the never-worse guarantee: a rule that doesn't match, throws, times out or says nothing leaves the base result exactly as it was, and nothing slows an ordinary link: the whole read, rewrite, page and endpoint, shares one `FETCH_TIMEOUT_MS` (8 s) deadline. Endpoint hosts are constants and only ids taken from the user's URL are interpolated, URL-encoded; responses and redirect targets are untrusted (check every field's type, `readLink` caps them with the shared limits and checks the image URL, HTML fragments go through `textOfHtml`, a rewritten URL goes through `parseHttpUrl` and the fetch guard). A link a rule answered for counts as read (`fetched: true`) even when its page wasn't. A title from the URL is a per-site opt-in, never a generic guess: an unread page on a site nobody has checked is titled host and path (`uber.com/en-US/blog/engineering`, not "En US").
  - The base workflow treats a page as unread (`INTERSTITIAL`) when a redirect lands on a consent, sign-in or bot-check host or path, or the page's title is exactly one of the well-known interstitial titles in `fetch.ts` ("Just a moment...", "Attention Required! | Cloudflare", "Access Denied", "Sign in", "Log in").
  - The rules: **Redirect wrappers** (shared): out.reddit.com (`url`), l.facebook.com and lm.facebook.com `/l.php` (`u`), google.com `/url` (`q` or `url`) and href.li (`?<url>`) are stored and read as their destination; l.instagram.com is left out, unverifiable. **YouTube**, **X**, **Hacker News**, **Stack Exchange**, **npm**, **Pinterest**: resolve from oEmbed, the HN Firebase API, the Stack Exchange API and the npm registry. **Reddit**: oEmbed title for a post, the "From the … community on Reddit: " prefix and the generic description dropped; a share link (`/r/<sub>/s/<code>`, `redd.it/<id>`) is followed to its post first. **Google Maps**: "Google Maps" is no title; a long link's title is the place in `/maps/place/<Name>/`; a short link (`maps.app.goo.gl`; the old `goo.gl/maps` links now fail at goo.gl and are left out) or a `?q=` link with no description gets the address from the `q` of its redirect, without the place's name and plus code (and its name as the title if the page gave none). **Google share** (`g.co/kgs/<code>`): " : Google Search" dropped, and the name from the redirect's `q` when the page gave no title. **Instagram**: a login-wall title ("Login • Instagram", "Instagram") is no title and the page counts as unread; a profile's title is "@<handle> on Instagram". **Medium** (shared): an article's title from its slug (`medium.com/<@user or publication>/<slug>-<id>`, `<name>.medium.com/<slug>-<id>` and the publications in `MEDIUM_PUBLICATION_HOSTS`, only with the trailing 10–12 digit hex post id). TikTok is deliberately not handled.
- Re-enrichment refreshes links saved before their site rule existed: `bunx convex run modules/link/mutations:reenrichInternal '{"userId":"<Better Auth user id>","dryRun":true}'` lists what it would touch (id, url, title, why) and changes nothing; drop `dryRun` to schedule it, and add `"domains":["youtube.com","x.com"]` to limit it to some sites (matched on the URL's host or the stored domain, subdomains included). It is an internal function, so only the CLI (dev, or `--prod` by the owner) can run it. It selects the user's links whose title is a stand-in (`isPlaceholderTitle`) or carries its site's decoration (`cleanTitle`), whose description is its site's generic one, that are redirect wrappers stored before wrappers were unwrapped, or that lack a field their site rule provides, such as a Maps link with no address (`reenrichReasons`, `modules/link/helpers.ts`), skips links already queued, and schedules `enrich` with `refresh` for up to 500 per call, spaced `IMPORT_SPACING_MS` apart after anything already queued; run it again for the rest. A title a site rule took from the URL ("@fatlulus on Instagram") is not selected again: it is the best that rule has. A refresh never replaces a real title (an imported Pocket title is real; a decorated one keeps its own words without the decoration), fills a missing description and image, replaces a site's generic description (any other description the link has stays), moves a wrapper link to its destination's URL unless another of the user's links already has it, and writes a new summary (against the global summary budget) only when the title or description changed; a failed model call keeps the old summary. The queued mark is `summaryDueAt` on a `ready` link, cleared when the run ends.
- A library holds at most `MAX_LINKS_PER_USER` links, because Home, tag statistics and `ask` read it whole. `create` returns `LIBRARY_FULL` at the cap and `importMany` inserts up to it and reports the rest as `full`. The count lives in the `linkCounts` table, changed by `changeLinkCount` (`modules/link/helpers.ts`) in the same mutation as every insert into or delete from `links`; any new path that adds or removes links must call it. Enrichment (`nodeActions.enrich`) always fills the metadata; when the global summary budget is spent it queues the summary again (backing off, up to five times) rather than failing it.
- Auth goes through this app's own origin: `/api/auth/$` (`src/routes/api/auth/$.ts`) proxies to the Convex site. This keeps the session cookie first-party, because there is no custom backend domain and Safari blocks third-party cookies. The auth client therefore has no `baseURL`. The root `beforeLoad` reads the Convex token from the cookie on every navigation, authenticates SSR queries with it, and puts `isAuthenticated` on the route context. Guards are in `src/modules/auth/guards.ts`: `requireSignedIn` sends signed-out visitors to `/sign-in?redirect=<path>`, and `redirectSignedIn` sends signed-in visitors on the auth pages where they were headed. `resolveRedirect` (`src/modules/auth/utils.ts`) accepts only same-origin paths. Signing in or up ends in a full page load, and signing out reloads, as the Convex Better Auth guide recommends.
- Better Auth rate-limits by client IP and path, stored in the component's `rateLimit` table (`storage: 'database'`; its in-memory default does not survive between Convex function runs): sign-in 5 a minute, sign-up 5 per 10 minutes, everything else Better Auth's 100 per 10 seconds; session reads (`/get-session`, `/convex/*`) are not limited. Convex sets `x-forwarded-for` from the connection, which for proxied requests is the app server, so the proxy (`modules/auth/server.ts`) sends the browser's IP (Vercel's `x-real-ip`) with `AUTH_PROXY_SECRET`, and `convex/http.ts` uses it only when the secret matches. Requests made straight to the Convex site are keyed on their own address. Without the secret on both sides, every proxied request shares the app server's bucket.
- There is no app-level users table. Better Auth keeps users and sessions in its component's tables. App rows are keyed by the Better Auth user id, which is `identity.subject` from `ctx.auth.getUserIdentity()`; get it with `getUserId` in `convex/modules/auth/helpers.ts`.
- Design direction "A · Index": a white page, ink `#141414`, hairline borders and one cobalt accent (`--primary`). Titles and the wordmark use `font-serif` (Newsreader), UI text uses `font-sans` (Outfit), and small metadata uses `font-mono` (JetBrains Mono). Every colour is a token in `src/index.css`; components never hard-code one. So are the in-between text sizes: `text-3xs` (10px tag counts), `text-2xs` (11px metadata and caps labels), `text-snippet` (13px descriptions under a title), `text-md` (15px big buttons and summaries) and `text-lede` (17px search field and answers); add a token rather than use an arbitrary size. The one allowed hex literal elsewhere is the `theme-color` meta in `src/routes/__root.tsx`, which cannot read a CSS variable (keep it equal to `--background`). Text tokens meet 4.5:1 on white and `--input` meets 3:1. The theme is light only, and nothing switches to dark. The layout is mobile first: wrap a page in `page-column`, which gives a ~640px centred column with 16px gutters and safe-area insets. Inputs are underlines, and primary buttons are cobalt pills.
- Dates: every date shown is formatted in `src/components/lib/dates.ts`, and every formatter takes an explicit `timeZone` (`groupByMonth` keeps one formatter of its own for the month key, for speed on a large library). `formatSavedDate`, `formatMonthLabel`, `groupByMonth` and `LinkRow` take a required `now` and `timeZone` (a `DateContext`), because "this year" and the calendar day differ between the server and the browser. Screens either render date-dependent output on the client only, or compute both once and pass them down so SSR and hydration agree.
- Share sends the URL as stored, with tracking parameters already stripped (`parseHttpUrl`). That is deliberate: the shared link is the clean one.
- Env: `.env.local` (gitignored) holds `CONVEX_DEPLOYMENT`, `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL`; `AUTH_PROXY_SECRET`, when the local proxy should pass on the IP, goes in the shell that runs `bun run dev`. The Convex deployment holds `BETTER_AUTH_SECRET`, `SITE_URL` (this app's origin), `OPENAI_API_KEY`, `AUTH_PROXY_SECRET` and, on dev only, `AUTH_TRUSTED_ORIGINS` (extra origins allowed to call auth, such as a second local port).
- Production: `https://webcase.rushilrai.me` on Vercel, root directory `apps/webcase`, build command `npx convex deploy --cmd 'bun run build'`, with `CONVEX_DEPLOY_KEY` set for Production only; the Convex CLI injects `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL` into the build. Vercel's Production environment also holds `AUTH_PROXY_SECRET` (runtime, same value as Convex's). The production Convex deployment holds `BETTER_AUTH_SECRET`, `SITE_URL=https://webcase.rushilrai.me`, `OPENAI_API_KEY` and `AUTH_PROXY_SECRET`. The app is private: `robots.txt` disallows everything and every page has `noindex`.
- Use the dev deployment only. Never run `convex deploy` or `--prod` from a worktree; production deploys belong to the owner.
