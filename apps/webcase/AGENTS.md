# apps/webcase

Webcase is a personal replacement for Pocket: a library of saved links. You save a link, it picks up the title, description and image, you tag it, and Home is one list with search and tag filters. It is an installable web app (PWA, no notifications) used mostly on a phone. Sign-up is open and each user sees only their own links. TanStack Start + React 19 (Router, Query, Form), Vite 8, Tailwind 4, shadcn on Base UI (tabler icons), Convex, Better Auth (email and password) through `@convex-dev/better-auth`.

Commands, run in `apps/webcase`: `bun run dev` (port 3000), `bun run build` (nitro, Vercel output), `bun run typecheck`, `bun run lint` (oxlint), `bun run check` / `bun run format` (prettier). There are no tests. `bunx convex dev --once` pushes functions to the dev deployment and regenerates `convex/_generated`. Commit the regenerated files.

- `src/routes/` holds TanStack file routes and stays thin. `src/screens/<area>/index.tsx` are the page bodies. `src/modules/<area>/` hold the data layer (`queries.ts`, `mutations.ts`, `schema.ts`, `components/`). `src/components/` holds only presentational pieces and the shadcn kit (`ui/`, `lib/utils.ts`). Providers are composed inline in `src/routes/__root.tsx`. Aliases: `@/` → `src/`, `@convex/` → `convex/`.
- Convex: `convex/modules/<area>/{schema,queries,mutations,actions,helpers}.ts`, with shared setup in `convex/configs/`. Handlers return `{ error: 'CODE' }` instead of throwing.
- Auth goes through this app's own origin: `/api/auth/$` (`src/routes/api/auth/$.ts`) proxies to the Convex site. This keeps the session cookie first-party, because there is no custom backend domain and Safari blocks third-party cookies. The auth client therefore has no `baseURL`. The root `beforeLoad` reads the Convex token from the cookie on every navigation, authenticates SSR queries with it, and puts `isAuthenticated` on the route context. Guards are in `src/modules/auth/guards.ts`: `requireSignedIn` sends signed-out visitors to `/sign-in?redirect=<path>`, and `resolveRedirect` accepts only same-origin paths. Signing in or up ends in a full page load, and signing out reloads, as the Convex Better Auth guide recommends.
- There is no app-level users table. Better Auth keeps users and sessions in its component's tables. App rows are keyed by the Better Auth user id, which is `identity.subject` from `ctx.auth.getUserIdentity()`; get it with `getUserId` in `convex/modules/auth/helpers.ts`.
- Design direction "A · Index": a white page, ink `#141414`, hairline borders and one cobalt accent (`--primary`). Titles and the wordmark use `font-serif` (Newsreader), UI text uses `font-sans` (Outfit), and small metadata uses `font-mono` (JetBrains Mono). Every colour is a token in `src/index.css`; components never hard-code one. The theme is light only, and nothing switches to dark. The layout is mobile first: wrap a page in `page-column`, which gives a ~640px centred column with 16px gutters and safe-area insets. Inputs are underlines, and primary buttons are cobalt pills.
- Env: `.env.local` (gitignored) holds `CONVEX_DEPLOYMENT`, `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL`. The Convex deployment holds `BETTER_AUTH_SECRET`, `SITE_URL` (this app's origin) and `OPENAI_API_KEY`.
- Use the dev deployment only. Never run `convex deploy` or `--prod` from a worktree; production deploys belong to the owner.
