# apps/webcase

Webcase is a personal replacement for Pocket: a library of saved links. You save a link, it picks up the title, description and image, you tag it, and Home is one list with search and tag filters. It is an installable web app (PWA, no notifications) used mostly on a phone. Sign-up is open and each user sees only their own links. TanStack Start + React 19 (Router, Query, Form), Vite 8, Tailwind 4, shadcn on Base UI (tabler icons), Convex, Better Auth (email and password) through `@convex-dev/better-auth`.

Commands, run in `apps/webcase`: `bun run dev` (port 3000), `bun run build` (nitro, Vercel output), `bun run typecheck`, `bun run lint` (oxlint), `bun run check` / `bun run format` (prettier). There are no tests. `bunx convex dev --once` pushes functions to the dev deployment and regenerates `convex/_generated`. Commit the regenerated files.

- `src/routes/` holds TanStack file routes and stays thin. `src/screens/<area>/index.tsx` are the page bodies, with their own pieces as siblings (`screens/home/AskResults.tsx`); split a screen or component once it holds several stateful parts. `src/modules/<area>/` hold the data layer and domain logic; e.g. `src/modules/link/utils.ts` has `groupByMonth` and `countTags`. The file kinds in a module:
  - `queries.ts` / `mutations.ts`: hooks over the Convex functions. Each `api.modules.<area>.*` function is wrapped once, in its own module (`modules/link` wraps every link query, mutation and action, including `useLibrary` with links, tag counts and status); other modules (`save`, `import`) build their orchestration on those wrappers. Stateful mutations use TanStack's `useMutation` unless one run spans many calls (the import runner, which says why).
  - `schema.ts`: zod schemas and the types derived from them, e.g. a route's search params (`modules/save/schema.ts`). Text search params use `searchText` from `src/lib/searchParams.ts`, because the router JSON-parses values (`?title=2048` is a number).
  - `errors.ts` (`modules/link`): `ErrorMessages<typeof fn>` keys copy by a function's error union, so a new server code is a type error; `messageFor` adds the generic fallback; `MESSAGES` is the one wording for codes that recur (`UNAUTHORIZED`, `INVALID_URL`, `NOT_FOUND`, network).
  - `hooks.ts`: React hooks with domain knowledge, e.g. `useReturnToLibrary` (go back to Home when Home opened the page, else replace) and `useSaveDraft`.
  - `utils.ts`: pure domain helpers. Narrower pure files are named for what they hold: `search.ts` (browser search), `share.ts` (system share sheet / copy), `csv.ts` and `pocket.ts` (the export parser), `file.ts` (reading a chosen file).
  - `components/`: components that use the module's data.
- `src/hooks/` holds generic hooks with no domain knowledge, one per file: `useClientDates` (the device's `now` and zone, null during SSR and hydration), `useRenderLimit` (render a long list a page at a time), `useKeyboardInset` (how far the on-screen keyboard covers the layout). `src/lib/` holds app plumbing (the Convex client, search-param parsing). `src/components/` holds only presentational pieces and the shadcn kit (`ui/`), e.g. `PageHeader` (the `‹ Library` header of a sub-page) and `SectionLabel` (the letter-spaced caps label); `src/components/lib/` keeps only pure display helpers (`cn`, the tag colour hash, date formatting). Providers are composed inline in `src/routes/__root.tsx`. Aliases: `@/` → `src/`, `@convex/` → `convex/`, `@shared/` → `shared/`.
- `shared/` holds rules both sides must agree on, as plain TypeScript that imports nothing outside `shared/`: `tags.ts` (`normalizeTag`, `normalizeTags`, `MAX_TAG_LENGTH` 40, `MAX_TAGS` 20, the `TagCount` type), `limits.ts` (URL, title, description, domain, image, question and import-batch limits, the import pace `IMPORT_SPACING_MS`, `DAILY_IMPORT_LIMIT`, `SUMMARY_STUCK_AFTER_MS`) and `url.ts` (`parseHttpUrl`, the normaliser links are stored and matched by, which drops the `TRACKING_PARAMS`; `domainOf`, `fallbackTitle`, `isPlaceholderTitle`). `src` imports it as `@shared/…`; Convex imports it by relative path (`../../../shared/tags`), which its bundler resolves without the alias. Never redeclare these rules elsewhere, and never import Convex code into `src` for them.
- Convex: `convex/modules/<area>/{schema,queries,mutations,helpers}.ts`. Every action goes in `nodeActions.ts`, which starts with `'use node'` and runs in the Node runtime (public ones are called as `api.modules.<area>.nodeActions.<name>`); `ai.ts` beside it holds the model calls and prompts those actions use, and is Node-only too. `convex/lib/` holds pure helpers the modules use (`lib/metadata/` for the server-only URL checks, the DNS-pinned page fetch and HTML parsing; `lib/text.ts`), and `convex/configs/` the shared setup (the AI provider, the rate limiter with its per-user and global buckets). Handlers return `{ error: 'CODE' }` instead of throwing, and mutations that have nothing else to return give `{ success: true }`.
- Auth goes through this app's own origin: `/api/auth/$` (`src/routes/api/auth/$.ts`) proxies to the Convex site. This keeps the session cookie first-party, because there is no custom backend domain and Safari blocks third-party cookies. The auth client therefore has no `baseURL`. The root `beforeLoad` reads the Convex token from the cookie on every navigation, authenticates SSR queries with it, and puts `isAuthenticated` on the route context. Guards are in `src/modules/auth/guards.ts`: `requireSignedIn` sends signed-out visitors to `/sign-in?redirect=<path>`, and `resolveRedirect` accepts only same-origin paths. Signing in or up ends in a full page load, and signing out reloads, as the Convex Better Auth guide recommends.
- There is no app-level users table. Better Auth keeps users and sessions in its component's tables. App rows are keyed by the Better Auth user id, which is `identity.subject` from `ctx.auth.getUserIdentity()`; get it with `getUserId` in `convex/modules/auth/helpers.ts`.
- Design direction "A · Index": a white page, ink `#141414`, hairline borders and one cobalt accent (`--primary`). Titles and the wordmark use `font-serif` (Newsreader), UI text uses `font-sans` (Outfit), and small metadata uses `font-mono` (JetBrains Mono). Every colour is a token in `src/index.css`; components never hard-code one. So are the in-between text sizes: `text-2xs` (11px metadata and caps labels) and `text-md` (15px big buttons and summaries); add a token rather than repeat an arbitrary size. The one allowed hex literal elsewhere is the `theme-color` meta in `src/routes/__root.tsx`, which cannot read a CSS variable (keep it equal to `--background`). Text tokens meet 4.5:1 on white and `--input` meets 3:1. The theme is light only, and nothing switches to dark. The layout is mobile first: wrap a page in `page-column`, which gives a ~640px centred column with 16px gutters and safe-area insets. Inputs are underlines, and primary buttons are cobalt pills.
- Dates: every date is formatted in `src/components/lib/dates.ts`, with an explicit `timeZone`. `formatSavedDate`, `formatMonthLabel`, `groupByMonth` and `LinkRow` take a required `now` and `timeZone` (a `DateContext`), because "this year" and the calendar day differ between the server and the browser. Screens either render date-dependent output on the client only, or compute both once and pass them down so SSR and hydration agree.
- Env: `.env.local` (gitignored) holds `CONVEX_DEPLOYMENT`, `VITE_CONVEX_URL` and `VITE_CONVEX_SITE_URL`. The Convex deployment holds `BETTER_AUTH_SECRET`, `SITE_URL` (this app's origin), `OPENAI_API_KEY` and, on dev only, `AUTH_TRUSTED_ORIGINS` (extra origins allowed to call auth, such as a second local port).
- Use the dev deployment only. Never run `convex deploy` or `--prod` from a worktree; production deploys belong to the owner.
